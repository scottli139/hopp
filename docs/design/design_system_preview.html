设计原则

面向开发者的桌面工具：密度、克制、可预期

1. 密度优先

对标 Postman / Insomnia / VS Code 的信息密度：正文 13px、辅助 11-12px、主控件高 32px。 层级靠字重与颜色表达，而不是堆砌字号种类——全局仅 7 档字号。

2. 单一事实来源

每个视觉值只有一个出处：token → ThemeExtension → 组件。 业务代码禁止出现颜色字面量、内联字号、魔法间距——由自动化守卫保证（见「执行保障」）。

3. 语义化命名

颜色按用途命名（surface / border / textSecondary / methodGet），不按色值命名。 暗色主题只是同一语义色的另一套取值，业务代码零分支。

4. 克制即专业

1px 分隔线只有两档透明度；圆角只有 4/6/8/10；阴影仅用于浮层（菜单、对话框）； 按钮无阴影、无渐变；品牌色只出现在需要引导视线的地方。

执行保障 · 让规范被强制遵守

规范无人遵守的根因：没有反馈回路。方案是把规范变成「跑在 CI 里的测试」和「看得见的组件目录」

① 设计守卫测试（核心）

test/design_guard_test.dart 静态扫描 lib/ 源码，CI 必过：
· 禁 Colors.xxx / Color(0x…)（白名单仅 lib/theme/）
· 禁内联 TextStyle(fontSize:) / fontFamily:
· 禁 BorderRadius.circular(字面量)
· 禁 withOpacity（统一 withValues / token）
现存违规记入基线文件，只减不增（ratchet），新违规直接 fail。

② 组件 Gallery + Golden Test

test-mode 新指令 open_design_gallery：一页展示全部 token 与组件的双主题渲染， 作为视觉验收基准；核心组件配 matchesGoldenFile 测试，样式回归直接变红。

③ 截图审计固化

integration_test/ui_audit_screenshots.py 一键遍历主界面/各对话框 × 亮暗双主题截图， 纳入 TESTING.md 验收流程；UI 改动提交前必须跑一遍对照。

④ 规范镜像 + 守门条款

重写 docs/UI_UX_GUIDELINES.md 与代码一一对应（真实类名、真实数值）， 删除文档中不存在的 NeutralColors/AppSpacing 等幽灵类； AGENTS.md 增加「UI 变更四步」：查规范 → 用 common 组件 → 过守卫测试 → 截图对照。
